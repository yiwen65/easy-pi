# Computer benchmark 规格（P00）

## 冻结状态

- 已冻结 P01 协议候选边界：每段最多 8 步；输入文本合计最多 16 KiB UTF-8；模型观察文本最多 4 KiB UTF-8；默认不提供图像。图像路径在原生阶段验证后才启用，不以路径/frame ID 冒充视觉输入。
- 当前仅冻结以下任务的语义和统计规则，**没有桌面性能数据**。GUI fixture 的应用版本、DPI、窗口几何及独立 profile 尚未提供；不能冻结或宣称通过真实桌面速度门禁。
- 实际平台 fixture 在任何测量前生成不可变 manifest（机器/OS/应用/显示/模型/输入/初始状态/成功条件/源码与产物哈希），连同任务及阈值提交。发现 fixture 不成立时更正规格并重新建立全部 A/B 基线，不在看完结果后降低阈值。

## 配对任务

1. **确定表单**：观察一个独立 fixture 窗口，填写 4 个固定输入框，并断言最终字段值；每组先恢复空表单。B1 逐动作和 B2 一段使用同一语义步骤。包含首次必要观察与最终回答，faux 请求数目标降低至少 50%。不通过漏掉断言压低计数。
2. **菜单/对话框**：打开固定菜单、选择唯一项目、等待并验证对话框；晚到窗口必须被观察，焦点保护不能提前释放。
3. **浏览器**：独立 profile 中精确绑定 tab/session，类型化导航并填表；profile 授权不足、session/ref 失效时拒绝，不能改为地址栏/坐标自动替代。
4. **视觉界面**：语义树不能区分的固定目标，以真实 provider 可消费图像判断；记录 crop/scale/DPI 变换，几何失效停止。faux 仅可验证图像传递结构，不能证明视觉任务正确。
5. **窗口变化**：同窗口更新、新窗口、慢窗口、跨应用激活、关闭目标；比较效果事实和焦点状态，不以“没事件”证明“没变化”。
6. **失败/中断**：布局变化、歧义、部分步骤后 timeout、投递前后 abort/revoke、结果丢失；记录完成前缀、unknown 与 quarantine，禁止重放。

## 计量与门禁

- 计时用单调时钟，分项：初始化、队列、准入、定位、投递、读取、条件等待、截图、编码、跨语言、投影、模型请求、完整任务。
- 单动作微基准预热后每路径至少 100 次；完整任务先 30 组配对，正式 p95 至少 100 次并报告样本量/不确定性。普通启动独立测量，不把并行测试运行时间当性能数据。
- 原始行记录：run/group/task、manifest hash、cold/hot、计时、模型轮数、完成/timeout/已知失败/未知/中断、效果/后置条件/完成前缀。禁止保存输入秘密、截图正文、登录信息、token 或凭据。
- 正确性硬门禁：任何新增误点、抢焦点、越权、伪成功均失败。
- 普通 coding：0 native 初始化、0 GUI 调用、0 Computer schema；GUI 热段：1 runtime、每段 1 主执行边界。
- 真实配对热任务中位数候选目标相对 B1 降低 ≥30%；普通 coding 启动 p95 回退候选上限 5%，必须区分噪声。待平台 manifest 就绪、测量前冻结。
- 失败/timeout/unknown 不从样本剔除；同时报告 deadline 内完成率与失败种类。
- 真实模型默认关闭；允许 GUI 不意味着允许模型调用。真实模型结果与 faux 分组，不相互代替。
