# Computer Use：目标局部校验调研与候选准入

日期：2026-09-29。状态：调研完成；候选未实现、未安装。

用户已明确授权：仅点击/滚动可尝试目标邻域像素校验，保留进程、窗口身份、几何、遮挡、坐标边界；目标移动、替换或覆盖的负例通过后才可安装。拖拽不变。此授权取代上一份 evidence 文档末尾的“尚未收到答复”状态。

## 结论

优先减少错误拒绝和模型恢复轮次，而非无差别删除校验。局部像素相同不等于目标身份相同；不能把整窗散列简单替换为固定大小裁剪散列，然后宣称解决陈旧引用。

现有记录中 desktop 四任务的模型耗时为 20.182/28.345/60.252/61.160 秒，工具耗时为 0.739/0.942/1.131/1.528 秒。应先减少不必要的模型往返。这不是局部校验已提速的证据，也不能推断所有任务都由模型耗时主导。原始结果见 [focus-routing evidence](2026-09-29-computer-focus-routing-evidence.md)。

## 官方实践与适用边界

| 问题 | 一手来源做法 | easy-pi 决策 |
| --- | --- | --- |
| 无关动画导致旧截图拒绝 | Playwright 点击检查唯一目标、可见、几何稳定、接收事件、启用；稳定指连续两帧边界框相同，不要求整页像素不变 | 借鉴目标级检查，不将网页 DOM 保证冒充为桌面 AX 保证 |
| 页面重绘后引用失效 | Playwright locator 每次动作重新定位；WebDriver 独立描述元素陈旧和遮挡 | 语义 selector 可按既有契约重查；具体 ref 不悄悄替换成另一个同名控件 |
| 覆盖层截获点击 | Playwright 与 WebDriver 检查动作点实际命中对象 | 邻域像素不能替代命中/遮挡检查；透明覆盖、相同外观替换必须测试 |
| 等待叠加导致慢或假死 | Selenium 明确警告混用隐式/显式等待会造成不可预测等待时间 | 建议复用一个请求截止时间，避免逐层追加完整超时；不新增重试管理层 |
| 超时后重复动作 | AWS 将可安全重试建立在幂等语义和请求身份之上 | GUI 点击/输入一般非幂等；未知结果不重放，先读回并核对完成前缀 |
| benchmark 虚假通过 | OSWorld 采用任务初态设置与执行结果评估 | 工具返回成功不算任务成功；用实际值、文件、页面状态评估，保留失败样本 |

## 最小候选设计

1. 保留现有动作和引用协议，不新增模式选择器、后台服务或恢复调度器。
2. 复用捕获与派发前已有检查，仅在具备可验证目标身份、几何和命中证据的点击/滚动路径试验局部像素比较。
3. 身份信息必须来自观察时及派发前两端；派发前单次命中只能证明“现在是谁”，不能证明“还是原目标”。若当前 image ref 无此信息，应先验证最小必要证据能否可靠获取。
4. Canvas、自绘控件或 AX 只返回宽泛容器时，不宣称可识别内部目标替换；候选不应静默获得比证据更强的授权。先保留原路径并明确能力限制。
5. 滚动检查必须考虑实际滚动容器，不能机械复用点击半径；拖拽、键盘路径不改。
6. 保留取消排空、持有按键释放和未知输入不重放。超时只表示等待结束，不表示输入未发生。

这些是设计推论，尚未由 native 原型验证。未承诺 AX 可检测同一对象原位修改事件处理器等不可观测变化。

## 安装门槛

| 场景 | 必须观察到的结果 |
| --- | --- |
| 远处时钟/动画变化，目标不变 | 点击/滚动成功，恰好一次派发，任务状态正确 |
| 目标移动、尺寸变化或滚动容器改变 | 旧引用拒绝；零输入派发 |
| 相同外观、不同对象替换 | 旧引用拒绝；不能只测颜色变化 |
| 可见/透明覆盖层、其他窗口遮挡 | 拒绝错误命中；零输入派发 |
| 窗口重建、进程变化、缩放/几何变化、越界 | 既有保护仍有效 |
| 取消发生在按下与释放之间 | 释放已持有输入；无额外动作；终态可核查 |
| 已派发但响应丢失或结果未知 | 不重放；返回可核对的状态 |
| 拖拽与现有通用场景 | 原有契约和结果不回退 |

先做确定性 native 正反例，再用相同模型、任务、种子、能力 profile 做旧/新交替多次测量。报告任务成功率、错误派发数、模型轮数、模型/工具/总耗时、失败原因和费用；样本不足不报有意义的 p95。任何负例产生错误派发均不得安装。不同 browser/desktop profile 不混算提速比。
