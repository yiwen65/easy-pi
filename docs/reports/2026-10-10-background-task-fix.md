# Background task 修复验证

已修复先前测试确认的四项问题，默认并发上限仍为 8，未包含模型策略和通知投递模式的优化改动。

| 问题 | 修复 | 验证结果 |
|---|---|---|
| 并发启动绕过上限 | 将准入检查放在异步验证之后，与任务注册保持同步连续执行 | 上限 1 的同轮双调用只接纳一个，另一个报容量错误 |
| shell 退出后子进程残留 | 停止期间检查进程组；仍有成员时保留 stopping 和 SIGKILL 宽限，完成组清理后才发布终态 | 真实 CLI 子 PID 17662 在 wait_for 返回后不存在；取消、后台超时均有回归 |
| 最后请求期间完成导致 wake 滞留 | 正常轮次收尾时批量转入一次 follow-up；显式取消、停止/销毁、错误和截断响应不通过此路径续跑 | sleep 1 场景收到一次带 WAKE_FIXED 的通知，共 3 回合；取消后不自动唤醒 |
| 日志截断后继续追加小块 | logTruncated 后直接跳过文件写入，继续维护内存 tail 和输出字节数 | 16 字节预算触发标记后文件无 END，wait_for 仍返回完整输出 |
