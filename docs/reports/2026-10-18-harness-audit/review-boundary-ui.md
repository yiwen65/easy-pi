- Axis: Security

- Problem: The new cwd branch passes `resolve(request.cwd, invocationCwd)` without resolving symlinks. `recursiveDeleteBase` then collapses `..` lexically before realpath. Reproducer (permission-only; do not execute deletion): create temporary `T/workspace/sub` and `T/outside`, then symlink `T/outside/entry -> T/workspace/sub`. Inspection establishes `allow`: the assessed target becomes `T/outside`, which covers no protected root. But the spawned process is physically in `T/workspace/sub`; `../*` targets workspace contents. - Recommended fix: Resolve the existing invocation directory physically after the same URL/home/lexical normalization used by execution, before interpreting relative command paths. Keep protected roots unchanged. Add the above symlink-cwd unit regression and a non-deleting backend integration case; retain scratch-cleanup allowances.

### Revoke failed-factory APIs so in-flight callbacks cannot repopulate cleaned state
- Severity: Medium
- Axis: Correctness
- Location: `packages/coding-agent/src/core/extensions/loader.ts:579-595`, provider/flag/event API guards; `packages/coding-agent/src/core/event-bus.ts::createEventBus`.
- Problem: Cleanup unsubscribes listeners, but the `finally` block sets `loading=false` for failed factories too. Every API guard checks only the shared runtime's activity, which stays active for successful extensions. Already-running async event handlers therefore resume after failure and write directly into shared provider queues, defaults and subscriptions. Deterministic reproducer: a factory subscribes an async `start` handler that awaits a gate, then registers a provider, a default flag and another listener; it emits `start` and throws. Await the rejected load, release the gate and await the handler's completion. The failed factory's registrations now survive. EventBus unsubscribe removes future delivery, not the suspended handler.
- Impact: An extension reported as unloaded can still change provider/default state or recreate listeners, defeating the intended factory rollback without any external-side-effect rollback requirement.
- Recommended fix: Track failed/discarded state separately from loading and reject subsequent calls through that factory's API; do not invalidate the shared runtime. Add the gated-listener regression and verify earlier successful extensions remain usable.
- Certainty: High confidence — direct loader/EventBus lifecycle trace; not executed. Existing new tests cover registrations before the throw and interleaved successful factories, not an already-running callback resuming afterward.
